The app now collects every registered route pattern from an `onRoute` hook and its not-found handler answers `405` with an `Allow` header naming the methods that path does serve, in the same error envelope under a new `method_not_allowed` code (`src/lib/method-allowed.ts`), localised like every other message. - **Embedded related records on the voucher routes** (#167): `GET /vouchers` and `GET /vouchers/:id` accept `?include=receipt,provider`, so a voucher page can render the receipt and the clinic without a second request per row. `receipt` is the exact object `GET /receipts/:voucherId` serves (`null` for a voucher that has not settled) — on `GET /vouchers/:id`, which already carries the stored receipt row, asking for it returns this canonical shape instead of the raw row. `provider` is the exact object `GET /providers/:address` serves (`status`, `registeredAt`, cached `metadata` and the full service catalogue) in place of the `address`/`name`/`country` summary; without the parameter both routes respond exactly as before. The receipt and provider shapes are now built by shared serialisers (`src/lib/receipts.ts`, `src/lib/providers.ts`) used by both the embedding routes and the separate endpoints, so the two cannot drift; `/providers/:address` therefore lists services ordered by code. `GET /vouchers` gains a `receipt` key in the `?fields=` allow-list. No schema change, so no migration. Tests in `src/__tests__/routes.test.ts`, including a query-counting route test that asserts a five-row page makes the same number of Prisma operations as a one-row page (`queryStats` in `src/db.ts`, counted only under `NODE_ENV=test`). README and `openapi.json` updated.

- **Live voucher updates over server-sent events** (#50): `GET /stream?voucher=<id>` / `?provider=<address>` (`src/routes/stream.ts`, registered in the same `/v1` + legacy alias pair as everything else) forwards each voucher transition as the indexer commits it — one `data:` frame with `type`, `voucherId`, `providerAddress`, `status`, `ledger`, `txHash` and `at`. Exactly one filter is required and the frame never carries a beneficiary reference, even though `voucher_created` has one on chain; nothing is read from the database to serve a stream, so the push channel cannot become a way to walk the read model. `src/lib/event-bus.ts` is the in-process bus: the indexer publishes **after** the transaction (or savepoint) that wrote the row commits, so a rolled-back event is never announced and a client is never told about a state the API cannot yet serve; publishing is best-effort and its failure is logged, never allowed to fail an indexer cycle. Idle streams emit a `: heartbeat` comment every `SSE_HEARTBEAT_MS` (new, default 15s), a client that cannot drain its writes is disconnected instead of buffering, one process holds at most `SSE_MAX_CONNECTIONS` (new, default 64) streams and answers `503 stream_full` past that, `/stream` is `Cache-Control: no-store`, and a `preClose` hook ends open streams so SIGTERM is not left waiting on an idle socket. The new `stream_connections` gauge on `/metrics` reports how many are held. `render.yaml` is unchanged: combined mode has the indexer and the streams in one process, which is the shape this needs (an API-only process has nothing to subscribe to and only beats). Tests in `src/__tests__/stream.test.ts`, driven over a real socket.
- **Atom feed of protocol activity** (#155): `GET /feed.xml` (`src/routes/feed.ts`, registered in the same `/v1` + legacy alias pair as everything else) serves the last 20 entries of protocol life as an Atom 1.0 document, newest first, for journalists, funders and community members who follow the project in a feed reader rather than a website. Two kinds of entry: settled vouchers, dated from the `Receipt` the chain minted so the timestamp is the settlement and not the row's last write, and newly verified clinics, taken from `ProviderStatusChange` rows whose status is `Active` so a suspension never reads as a verification. Each entry links to the JSON route that proves it (`/v1/vouchers/<id>`) and names the care as well as the clinic through the batched label/clinic lookups the receipt routes already share — four queries for the whole document regardless of what matches, never one per row. Because a feed is polled, cached and syndicated by third parties beyond anyone's control, the route **never selects `beneficiaryRef`**: entries are built with `serialiseReceipt()` (`src/lib/receipts.ts`), whose input type excludes the column, and a test asserts the reference value and the word "beneficiary" appear nowhere in the bytes. Clinic names are arbitrary on-chain text, so every value passes through the five predefined XML entities, and a test registers a clinic named `Maternity & <Child> Health` to prove the document still parses. The acceptance criterion asks for validation by a feed validator in a test; the npm packages that do it are XML parsers with an Atom layer bolted on, so `src/__tests__/feed.test.ts` carries a strict reader instead — it rejects the malformed-XML failures a validator rejects (an open tag, a mismatched end tag, a second root, a bare `<`, an `&` that starts no entity, a duplicate attribute) and the RFC 4287 mandatory parts (namespace, feed `title`/`id`/`updated`, `rel="self"`, per-entry `title`/`id`/`updated`, unique ids, author inheritance, content or summary). `/feed.xml` joined `CACHEABLE_ROUTES`, so it is `Cache-Control: public, max-age=5` with the usual indexer-cursor `ETag` and `304 Not Modified` on a matching `If-None-Match`, and it uses the tighter `LIST_ROUTE_RATE_LIMIT` (30/min) like the other routes that scan the read model. An empty read model is a valid feed with zero entries, not a 404. No schema change, so no migration; no new dependency. Tests in `src/__tests__/feed.test.ts`. README (endpoint table, "Response behaviour" and a curl example), `docs/privacy.md` (a route row and the bulk-channel redaction rule) and `openapi.json` updated.

### Security
- **Stellar addresses are checked against their checksum** (#171): the `funder` and `provider` filters on `GET /vouchers`, `/vouchers.csv`, `/vouchers/due`, `/receipts` and `/stream` used to accept any 56 characters, so a typo came back as an empty result. They now go through the shared `accountAddress` zod schema (`src/lib/stellar-address.ts`, built on `StrKey.isValidEd25519PublicKey`), and a bad checksum is a `400 invalid_query` whose details say `must be a valid Stellar account address`. Tests in `src/__tests__/routes.test.ts` and `src/__tests__/stream.test.ts`.
- **Refuse wildcard CORS origin in production** (#56): `CORS_ORIGIN` now rejects `*` when `NODE_ENV=production` and validates origins as http(s) URLs.
- **Query parameter length caps** (#57): all string query and path parameters in route schemas now enforce `.max()` limits to prevent denial-of-service via unbounded query strings.

### Changed
- **A database outage answers `503 database_unavailable` with `Retry-After`** (#133): when the database is unreachable the read routes throw and every request comes back as a generic `500 internal_error`, which tells a client nothing about whether to retry. `errorEnvelope` (`src/lib/errors.ts`) now recognises the Prisma connection failures — an initialisation error (engine missing, server unreachable) and codes `P1001`, `P1003`, `P1008`, `P1009`, `P2024` — and answers `503` with the same envelope under a new `database_unavailable` code, localised like every other message, plus `Retry-After: 5` (the read model's own cache window; exported as `DATABASE_RETRY_AFTER_SECONDS`). The app-level error handler applies the headers the envelope returns. Everything else is unchanged: a query that is merely wrong (an unknown column, a duplicate key) is still a `500 internal_error` without `Retry-After`, a route's own `ApiError` is untouched, and the Prisma cause still goes only to the log line. No response shape, route or schema change, so no migration and no OpenAPI change. Tests in `src/__tests__/database-unavailable.test.ts`; README error-code list and `docs/logging.md` updated.
- **`src/lib/voucher_seq.ts` renamed to `src/lib/voucher-seq.ts`** (#170), with its test, to match the kebab-case naming of every other file in `src/lib`. Imports updated; no behaviour change. The applied migration `20260106000000_voucher_seq` keeps its name and contents, since editing an applied migration changes its checksum.
- **`GET /vouchers?sort=amount` and the `minAmount`/`maxAmount` band run in the database** (#96): they used to load every matching voucher, filter and sort it with BigInt in JS, then slice the page, so cost and memory grew with the match set (about 10× lower throughput than index order in `npm run loadtest`). New column `Voucher.amountKey` holds the amount zero-padded to 39 digits (the width of the largest i128), so string order is numeric order; it is indexed, sorted with the same `(seq, id)` tie-break as the other sorts, and paged with `take`/`skip`. The shared Prisma client in `src/db.ts` fills it on every voucher write that sets `amount`, and the seed and load-test scripts set it themselves. Migration `20260110000000_voucher_amount_key` adds and backfills it. A bound wider than any i128 now compares as a number would (min matches nothing, max matches everything). Response shapes are unchanged. Tests in `src/__tests__/routes.test.ts` and `src/__tests__/amounts.test.ts`.
- **`GET /stats` settled totals run in SQL on Postgres** (#60): `settledValue`, `feesCollected` and `settledVouchers` are no longer computed by fetching every settled voucher and summing decimal strings with BigInt **when the database is Postgres** — one `SELECT COUNT(*)::int, COALESCE(SUM("amount"::numeric), 0)::text, COALESCE(SUM("settledFee"::numeric), 0)::text` aggregate does it in the database, exact over the whole i128 range (`numeric` is arbitrary-precision; the `::numeric` cast is valid today on the `text` columns and becomes a no-op once the pending `20260107000000_amount_numeric_to_decimal` migration is promoted with the schema flip). The route branches on the existing `isPostgres` flag (`src/lib/database.ts`); on SQLite the exact BigInt pass stays, because SQLite caps integer arithmetic at 2^63-1 and would silently round larger sums through float64, violating the repo's "i128 as strings, never numbers" rule. Response shape and strings are unchanged; the SQLite route tests are untouched and a new one pins the i128-max sum. Verified against a real Postgres (exact totals incl. i128-max, before and after the pending migration's `ALTER ... numeric`, empty-table `'0'` parity) — see `docs/amount-numeric-migration-plan.md`.
- **`GET /version`** (#19): now reports `version` read from `package.json` at startup (previously a hard-coded literal that had drifted from the package), `commit` from `RENDER_GIT_COMMIT`, then `GIT_COMMIT`, else `null`, the `indexerStartLedger` this deployment was configured with, and `startedAt` for the process. The existing network, RPC and contract fields are unchanged, and the response stays an allow-list so no secret can appear in it. Tested in `src/__tests__/routes.test.ts`.
- **`SHUTDOWN_TIMEOUT_MS`** (default `15_000`): how long the indexer waits for its in-flight cycle on shutdown, and the bound the process uses before its hard exit.
- **Versioned migrations**: production now applies reviewed migrations from `prisma/migrations/` with `prisma migrate deploy` instead of `db push --accept-data-loss`. `20260101000000_init` is the Postgres baseline of the previous schema and `20260102000000_failed_events` adds `FailedEvent`. A CI `migrations` job applies them to a fresh Postgres and fails if the schema and migrations drift. **Existing production databases must run `npx prisma migrate resolve --applied 20260101000000_init` once** (see README "Deploying").
- **Batched indexer writes**: all events from one poll cycle are applied in a single transaction together with the cursor update, with a savepoint per event so a failing event rolls back only itself. A crash mid-cycle leaves the cursor unchanged.

### Added
- **Indexer backoff on RPC errors**: a failed cycle now doubles the wait before the next one (`nextDelay`, exponential from `INDEXER_POLL_MS` with 25% jitter, capped by the new `INDEXER_BACKOFF_MAX_MS`, default 60s) and resets on the first cycle that works. The failure is logged once per streak instead of once per attempt, with a matching `indexer recovered` line carrying the attempt count.
- **RPC failover**: `SOROBAN_RPC_URLS` takes a comma-separated list of endpoints; `SOROBAN_RPC_URL` still works and is used when the list is unset. After `SOROBAN_RPC_MAX_FAILURES` consecutive failures (default 3) reads move to the next endpoint and the switch is logged. `/version` reports every configured endpoint and `/ready` reports the active one as `checks.rpcUrl`, both redacted.
- **Reconciliation against the chain**: `npm run indexer:reconcile [-- --fix] [-- --sample <n>]` compares every non-terminal voucher (plus a rolling sample of terminal ones, default 25) with `get_voucher` through simulation. Differences are recorded in the new `ReconcileMismatch` table and exposed on `/ready` as `checks.reconcileMismatches` and `checks.reconcile`. Drift is reported but does not make `/ready` 503: unlike a failed event it says nothing about whether the instance can serve traffic. `--fix` rewrites the differing rows from chain state; the command exits non-zero while any mismatch is open. See `docs/RUNBOOK.md`.
- **Faucet drip counts**: with the optional `FAUCET_CONTRACT_ID` set, the indexer subscribes to the testnet faucet and projects its `dripped` events into the new `FaucetDrip` table (keyed by on-chain event id, so replay cannot inflate the count). `/stats` gains `faucetDrips` and `faucetWallets` (distinct wallets), both `0` when no faucet is configured.
- **Prometheus metrics**: `/metrics` serves Prometheus text with default process metrics, `indexer_lag_ledgers`, `indexer_seconds_since_success`, `events_applied_total{name}`, `events_skipped_total{name}`, and `http_requests_total` / `http_request_duration_seconds` labelled by route pattern. It is exempt from the public rate limit. Indexer series are populated in the process that runs the indexer (combined mode or the worker).
- **Dead-lettered events**: an event that fails to project is stored in the new `FailedEvent` table (id, name, ledger, raw XDR, error, attempts, first/last seen) instead of only being logged. `/ready` reports degraded while any exist (`checks.failedEvents`). `npm run indexer:retry-failed` re-decodes and re-applies them, deleting rows that succeed. The table is created by the `20260102000000_failed_events` migration.
- **Load test harness and report**: `npm run loadtest` (autocannon) seeds a throwaway SQLite database, starts the API, and measures three read-API scenarios. Reference results (with p50/p97.5/p99, errors and hardware) and method notes in `docs/load-test.md`. The `sort=amount` bottleneck it surfaced is filed upstream as issue #96.
- **Mutation testing**: `npm run mutation` runs Stryker against `src/lib/lifecycle.ts` and `src/lib/amounts.ts`. Local-only by design (not in CI). Current score 100%; the two equivalent `StringLiteral` mutants are annotated inline, and method notes live in `docs/mutation-testing.md`.
- **OpenAPI spec and Swagger UI**: `@fastify/swagger` generates the spec from Zod schemas. Served at `/docs` (Swagger UI) and `/openapi.json` (raw spec). Amount fields documented as decimal strings.
- **Cursor pagination**: All list endpoints accept `cursor` and `limit`. Responses carry `nextCursor` (null when exhausted). Cursors encode `(createdAt, id)` as base64url. Offset pagination kept with a `Deprecation` header for one release.
- **RPC retention gap detection**: The indexer detects when its cursor falls outside the RPC retention window, marks itself degraded (`gap` flag in `IndexerState`), and `/ready` returns 503 with gap details and a pointer to `docs/RUNBOOK.md`.
- **Backfill command**: `npm run indexer:backfill -- --from <ledger> [--to <ledger>]` replays events without touching the cursor. Idempotent; refuses to start before the RPC retention window.
- **`docs/RUNBOOK.md`**: Recovery procedures for the retention gap.
- **`/v1` API versioning**: every route is also served under `/v1`. The unversioned paths remain as aliases and carry `Deprecation: true` plus a `Link` header naming the `/v1` successor.
- **`X-Request-Id`**: accepted (validated, log-safe) or generated, echoed on every response and present as `reqId` in the matching log line.
- **GET /vouchers.csv**: streamed RFC 4180 CSV export with the same filters as `GET /vouchers`. At least one filter is required and there is no beneficiary reference column.
- **GET /services**: Service catalogue across active clinics, grouped by code, with unique labels, clinic count and min/max/median price. Aggregates are computed with `BigInt`; the median of an even number of prices is the floor of the mean of the two middle values.
- **GET /services/:code**: Active clinics offering one service code, cheapest first, each with `price` and `priceDisplay`.
- **GET /countries**: Countries with at least one active clinic and their clinic counts, for building filters without paging every provider.
- **GET /providers?q=**: Case-insensitive clinic name search, length-capped at 64 characters. Uses `mode: 'insensitive'` on Postgres; SQLite's `LIKE` is case-insensitive for ASCII.
- **GET /vouchers sort options**: `?sort=createdAt|expiresAt|amount` and `?order=asc|desc` (defaults `createdAt`/`desc`, matching previous behaviour). `amount` is sorted numerically with `BigInt`, not lexicographically; ties fall back to the voucher id in the same direction.
- **GET /receipts?provider=**: List receipts by clinic/provider. Beneficiary references omitted in this view.
- **GET /receipts/:voucherId**: Fetch a single receipt by voucher ID for shareable receipt pages and verification. No beneficiary reference in response.
- **GET /vouchers/due?within=72h**: Vouchers needing action soon (expiring, becoming refundable, or settleable) with funder or provider filter. Uses lifecycle logic from `src/lib/lifecycle.ts` so API and contracts agree.
- **Multi-status filter for vouchers**: `?status=Claimed,Attested` accepts comma-separated list validated against the status enum; invalid values rejected.
- **`READY_MAX_LAG_LEDGERS`** (default `120`): lag in ledgers at which `/ready` reports degraded. The response echoes it as `checks.maxLagLedgers`.
- **Split API and indexer entry points**: `npm run start:api` and `npm run start:indexer`; combined `npm start` stays the default. Commented two-service example in `render.yaml`.
- **Indexer lease**: `IndexerState.leaseOwner` / `leaseExpiresAt` make the cursor single-writer. Standby instances log and retry instead of racing the cursor.
- **Attesters**: `Attester` model (`active`, `addedAt`, `removedAt`) and `Voucher.attestedBy`. The indexer now projects `attester_added` / `attester_removed` and records the attester from the `voucher_attested` topic instead of discarding it.
- **GET /attesters**: Active attesters by default, `?all=true` to include removed ones, each with its attestation count. **GET /attesters/:address** for one attester with its count.
- **Dispute resolution**: `Voucher.disputeResolvedAt` / `disputeResolvedBy` / `disputeOutcome` (`Funder` | `Provider`), projected from `dispute_resolved` and returned by `GET /vouchers` and `GET /vouchers/:id`.
- **GET /vouchers/:id/events**: the voucher's contract events in ledger order, each with its transaction hash, backed by a new append-only `ContractEvent` log.
- **Postgres CI matrix**: the suite now runs on Postgres as well as SQLite. `test/global-setup.ts` honours a provided Postgres `DATABASE_URL`, resetting by dropping and recreating the schema.
- **Automated dependency updates**: `.github/dependabot.yml` opens one grouped npm PR a week (minor and patch) and one for GitHub Actions. Prisma updates arrive as their own PR labelled `do-not-merge`, so the auto-merge bot holds them until a maintainer has looked.
- **CodeQL analysis**: `.github/workflows/codeql.yml` analyses JavaScript/TypeScript on pull requests into `main`, weekly and on demand, uploading results to code scanning. `src/__tests__/ci-workflows.test.ts` asserts the workflow keeps its triggers, permissions and actions.
- **Uptime monitoring**: `.github/workflows/monitor.yml` probes the deployed `/ready` every 30 minutes, retrying so Render free-tier cold starts do not fail the run, and its badge is in the README. `docs/RUNBOOK.md` documents the free UptimeRobot setup, the alert contact and why `/ready` is the endpoint to watch rather than `/health`.
- **Dependency audit in CI**: an `audit` job runs `npm audit --omit=dev --audit-level=high` on every pull request. High and critical advisories in production dependencies fail the build; moderate findings are reported but tolerated. The threshold is the `--audit-level` flag in `.github/workflows/ci.yml`.
- **`docs/architecture.md`**: the indexer pipeline from RPC to API — paging and decoding, the cursor and lease model, idempotency rules and failure modes — linked from the README and `CONTRIBUTING.md`.

- **Indexer transactions**: each event's projection and its `ContractEvent` log insert now commit in one database transaction, and the per-handler transactions were folded into it.
- **Known events**: `attester_added`, `attester_removed` and `dispute_resolved` are now projected rather than ignored.
- **`Voucher` schema**: three nullable dispute columns and a nullable `attestedBy` added; `prisma db push` adds them in place (no backfill needed).
- **README environment reference**: the Environment table now documents every variable `src/env.ts` accepts, with Required, Default, Example and description columns; `STELLAR_NETWORK` was missing. `src/__tests__/env-docs.test.ts` fails when the table and the schema drift apart.

### Fixed
- **Voucher id ordering** (#61): `Voucher.id` is the on-chain u64 kept as a string, so every `ORDER BY id` was lexicographic and put voucher 10 before voucher 9. `Voucher` now carries a numeric `seq` mirror of the id, written from the id by the `voucher_created` handler (`voucherSeq()` in `src/lib/voucher_seq.ts`) and backfilled for existing rows by migration `20260106000000_voucher_seq`; `GET /vouchers` (both the sorted page and the keyset cursor), `GET /vouchers.csv` and the amount-filtered page all sort by `seq`, with `id` kept as the final tie-break. `seq` is `BIGINT` rather than `Int` because the seeded id space starts at 9e12, and it is null for a hand-written id that has no numeric value (`bulk-0001`), which then sorts last in both directions so no row can fall between two pages. No response gained a field. Tests in `src/__tests__/voucher_seq.test.ts`.
- **tests:** vitest now collects only `src/**/*.test.ts`. The `node:test` suite at `.github/scripts/automerge.test.cjs` has its own CI job, but was also being collected by vitest and failed `npm test` as "no test suite found".
